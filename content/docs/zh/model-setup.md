本页接续 [安装 DeepSeekBot](/zh/docs/installation)，介绍如何配置模型服务并为每个 Bot 指定模型。你需要先在全局设置中配置好 API 提供商，再为具体的 Bot 选择模型；同一个提供商可以供多个 Bot 共用。

## 1. 在 DSH 配置模型提供商

点击左下角 **设置 → 模型**。如果要修改已有提供商，点击其右侧的 **编辑**；如果要新增，点击 **添加模型提供商**。

- **第三方模型提供商**：从内置目录中选择服务商，填写对应的 API 密钥，点击 **保存**。如果密钥是通过启动环境变量传入的，输入框会显示只读提示，请在启动环境中管理该密钥。
- **自定义模型 API**：适用于兼容接口、中转网关或自部署服务。填写下方字段并添加至少一个模型后，点击 **创建提供商**。

![DSH 模型设置中的提供商目录与自定义设置](/guides/settings/model-provider-catalog-zh.webp)

| 参数 | 填写方式与作用 |
| --- | --- |
| 提供商 | 内置目录中的服务名称，决定请求适配器及默认模型列表。 |
| Provider ID | 自定义提供商的唯一标识，以小写字母开头（如 `acme-gateway`）。模型路由使用此 ID，显示名称不能替代它。 |
| 显示名称 | 你在界面中识别该提供商的名称。 |
| API 地址 | 服务商提供的接口基址（例如 `https://gateway.example/v1`）；内置提供商留空时会使用默认地址。 |
| API 协议 | 根据接口类型选择 OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages。 |
| API 密钥 | 对应服务的访问凭据。请在此处的凭据界面填写，不要写进 Bot 的人格文本或聊天消息中。 |
| 获取可用模型 | 从服务端拉取模型列表（需接口与凭据支持）。如果拉取失败，可手动添加服务商提供的模型 ID。 |
| 模型 ID | 请求中实际发送的模型标识，必须与服务商文档一致。 |
| 模型显示名称 | 模型选择器中展示的友好名称，不影响实际发送的模型 ID。 |
| 模型选项 → 上下文窗口 | 模型的上下文容量，按服务商规格填写，支持 `256K` 等格式。 |
| 模型选项 → 最大输出 token 数 | 单次回复的输出上限规格（如 `32K`），代表最大容量而非每次固定输出长度。 |
| 模型选项 → 输入类型 | 文本为必选；仅当模型实际支持视觉输入时才勾选图片。 |

![自定义 API 表单与单个模型的选项](/guides/settings/model-provider-custom-zh.webp)

内置提供商的 **自定义设置** 可以覆盖默认 API 地址和模型列表。如果提供商下没有任何可用模型条目，模型选择器将无法展示该提供商的模型，Bot 的模型预设也无法生效。保存提供商后，请继续完成下方 Bot 的模型选择。

## 2. 打开要配置的 Bot

关闭设置，进入 **Bot 模式**，打开目标 Bot 的私聊。在右侧 Channel sidebar 展开 **模型**，点击 **主模型** 卡片打开 **模型** 配置弹窗。各卡片的含义详见 [模型](/zh/docs/channel-sidebar/model)。

![Bot 私聊右侧 Channel sidebar 中的模型分区](/guides/channel-sidebar/14-model-zh.webp)

这里的设置仅针对当前 Bot 生效。左侧 **Bot 设置** 中的图标、排序和并发上限属于全局选项；DSH 的 **Agent 预设** 用于选择工具集和工作模式，与 Bot 的模型预设相互独立。

## 3. 选择模型并保存

你可以在弹窗里直接为 Bot 选择模型，无需先创建预设。

| 参数 | 用途 |
| --- | --- |
| 主模型 | Bot 接收消息、协调工作和日常对话所使用的模型。支持输入关键词过滤列表。 |
| 执行模型 | Bot 分派出去的后台任务在未单独指定模型时使用的默认模型。 |
| 思考强度 | 模型支持的推理档位。选「默认」则不强制指定档位；不同模型提供的档位选项可能不同。 |
| 进阶 | **执行模型** 旁的 **简单 / 进阶** 切换。默认简单模式只需选一个模型和一种思考强度。切换到进阶模式后，可配置多张模型卡片：在顶部添加多个候选模型，勾选每个模型允许的思考强度与默认强度，将其中一张设为默认，并可为每个模型填写适用场景说明。Orchestrator 分派新任务时会参考这些说明，在合适的场景自动选用更省 token 的模型。切回简单模式则只保存单个模型。 |
| 保存 | 为当前 Bot 保存这组设置，从下一轮对话开始生效。 |

![从侧栏打开的模型弹窗](/guides/channel-sidebar/15-model-dialog-zh.webp)

保存后，侧栏的两张卡片会显示更新后的「模型 · 思考强度」。不同的 Bot 可以自由搭配不同的模型组合。

## 4. 使用预设（可选）

预设是一组可复用的模型配置，适合让多个 Bot 共享同一套模型方案。

| 操作 | 生效范围 |
| --- | --- |
| 另存为预设 | 把弹窗里的当前设置存成新预设，并让当前 Bot 立即使用它。 |
| 从预设填入 | 用已保存的预设填满弹窗，点击 **保存** 后应用到当前 Bot。 |
| 改动任何一项 | 当前 Bot 会脱离与原预设的关联，按你修改后的设置独立保存；原预设本身保持不变。 |

后台任务所使用的模型在任务创建时即已确定。修改默认模型不会改变已创建任务的模型配置，也不会中断或重跑 Bot 正在生成的回复。

## 5. 确认模型已生效

返回聊天界面，发送一句简短消息。收到回复后，你可以打开 Bot 的资料页（点击聊天顶部名称或头像 → **查看详细**），在 **Token 用量** 中切换到 **按模型** 查看最新用量；如果想查看具体某次会话，也可以从右侧 **会话** 打开对应的 DSH Session，查看其中的模型选择器和每轮对话的用量记录。

![实际 Session 中的 DeepSeek Flash / High 选择器与应用预设后的回复](/guides/settings/model-session-verification-zh.webp)

如果保存了新的模型设置，已存在的会话会在下一轮对话时切换为新模型。正在运行中的后台任务可以在其对应的任务会话中查看实际使用的模型。

| 常见问题 | 排查方法 |
| --- | --- |
| 「没有可用模型」 | 回到 **设置 → 模型**，确认提供商已保存、API 密钥有效且模型列表不为空，然后重新打开模型弹窗。 |
| 「当前模型不可用」或提示需要修复 | 提供商或模型可能已被删除或改名；在模型弹窗里为 Bot 重新选择可用模型并保存即可。 |
| 没有回复或服务报错 | 核对提供商的 API 地址、协议、密钥、模型 ID 以及账户额度，建议先在本地私聊中测试连通性。 |
| 会话中的模型与预期不一致 | 打开对应 Session 检查模型选择器和最新一轮对话的 Token 用量，确认是否已在保存设置后发起过新一轮对话。 |

更多设置项说明请参考 [设置指南](/zh/docs/settings)。IM 渠道连接请参考 [Lark / 飞书](/zh/docs/lark-connection) 与 [Slack](/zh/docs/slack-connection)。
