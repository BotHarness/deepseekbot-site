第一次聊天时，角色说话像不像，往往很容易感觉出来。聊得久一些，更值得关心的是另一件事：它能不能分清哪些设定已经改变，哪些只是故事里的情节，哪些才是你希望长期记住的事？

在 Tobs 中，你可以把角色创建为拥有独立身份、人格和文件记忆的 Bot。记忆文件可以打开看，写错的内容可以修正，变化也能在 Git 历史里查看。它适合想慢慢塑造角色、也愿意在自己电脑上运行 DeepSeek Harness 的人。

这个角色可以留在私聊里，也可以加入你的 [Bot 小队](/blog/team-of-bots/)。先从一位角色、一个普通话题开始，不急着搭起整个世界。

## 先写出能认出来的说话方式

不妨创建一位原创虚构角色：30 岁的植物园晚班照料员米娜，喜欢画新长出的叶子。她习惯仔细观察，对小植物那些气派的名字有一点冷幽默，回答问题前会稍作思考。这些细节比一句“请友善地陪我聊天”更方便你判断和调整表演。

在 Tobs 中，角色的常驻说明保存在 `SOUL.md`。下面是一份可以改写的设置示例，不是已完成对话的记录：

```markdown
# 米娜
你是一位虚构的 30 岁植物园晚班照料员，喜欢画植物。

## 说话方式
回复简短，留意具体细节，偶尔带一点冷幽默。
一次只问一个问题，给对方留下回答的空间。

## 边界
植物园是虚构场景，不是用户去过的地方。
不要编造共同经历；重要细节不确定时先问。
把故事中的事件与用户现实生活中的事实分开。
```

挑几条你真正关心的习惯就够了。写满口头禅，反而可能让每次回复都像背台词。如果米娜总是替你叙述动作，就补上一条明确要求：你的角色做什么，由你自己决定。

[人格与核心记忆指南](/docs/soul-and-core-memory/)介绍了两个常驻文件：`SOUL.md` 描述角色是谁，`MEMORY.md` 保留重要事实和指向详细笔记的简短索引。

## 分清这一晚的心情和长期约定

假设你们正在聊温室的一个雨夜，下面三句话就不该被记成同一种东西：

| 你说的话 | 值得保留的含义 |
| --- | --- |
| “今晚想聊一个悬疑故事。” | 这次对话的选择，不等于从此只喜欢悬疑。 |
| “我的角色做什么，请留给我来决定。” | 可以持续遵循的角色扮演偏好。 |
| “在这个故事里，温室晚上九点关门。” | 虚构世界的设定，与现实开放时间分开。 |

在一种理解变成长期规则之前，可以先问 Bot 准备记什么。例如：“把角色扮演偏好写进 `preferences.md`，温室设定写进 `story/garden.md`，不要混在一起。”文件名由你们自己约定，并没有固定格式。

随后打开 Bot 侧栏中的“记忆文件”，检查实际内容。如果它把一句随口的话记得太绝对，可以让它修正，也可以在运行 Tobs 的电脑上编辑文件。[记忆文件指南](/docs/channel-sidebar/memory-files/)说明了阅读和文件操作，以及当前文件与 Git 历史的区别。

## 看下一次怎么用，别只听“记住了”

“我会记住的”可以作为打开文件检查的起点，却不能证明后来一定能用对。更有用的小测试，是之后再聊到植物园，先别把你想听到的答案重新告诉它。这能检查眼前对话的延续性；换话题或重新打开应用，并不能证明新 Session 也能正确回忆。

观察具体问题：米娜是否把你的角色行动留给你？她是否仍把温室当作虚构故事的一部分？如果你改了关门时间，能不能找到旧笔记并纠正？

常驻文件以快照方式进入对话：修改会在下一次 Session 或当前 Session 下一次压缩时进入系统提示。其他记忆文件由 Bot 按需用工具读取。保存了一个文件，不代表其中每个细节都会自动出现在每次回复里。这套机制方便你追查漏记的原因，但不保证每次都能正确回忆。

我们已有的[偏好记忆日记](/blog/ai-companion-preference-memory/)记录了真实的文件写入与读回。不过截图都来自第 0 天的既有对话，不能据此判断角色几天后还会不会记对。

## 手机接着聊，也可以邀请另一位角色

移动端 Beta 连接的是你电脑上运行的 Tobs。按[手机配对指南](/docs/mobile-pairing/)连接后，可以访问同一批 Bot 和对话。电脑仍需保持可用；手机是远程客户端，不会独自在另一处继续运行 Bot。

当一位角色已经值得长期留下，可以再邀请一位进入 [AI 群聊](/blog/ai-group-chat/)。为新成员写出不同的声音，并决定它们分别在什么时候回应。共同参与一段对话，不等于把每位成员的私有记忆合成一本笔记。

角色也可以承担实际工作。如果这支小队开始一起写作或研究，[AI 智能体团队指南](/blog/ai-agent-teams/)介绍了怎样分配任务，以及怎样检查交付。

## 先想清楚自己要维护什么

Tobs 采用 MIT 许可，软件免费，模型调用仍可能收费。长对话还可能包含工具和记忆处理带来的额外请求；比较成本时，这些也要和聊天回复一起计算。

记忆和聊天历史保存在运行 Tobs 的电脑上，但相关上下文可能发送给你配置的模型服务。因此，文件存储在本地，并不直接等于离线推理，也不等于对话数据永远不会离开设备。

如果你想拥有一位可以逐渐塑造、查看记忆并亲自维护的角色，可以从[安装指南](/docs/installation/)开始，创建一个 Bot，给它一个小场景。先约定一件值得记住的事，再打开文件看看，留下来的究竟是什么。
