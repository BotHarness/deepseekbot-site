## 可供编辑改写的资料稿

标题：**当 AI 助手开始长期协作，用户需要看清哪些交接？**

署名与关系：由 BotHarness / DeepSeekBot 项目团队提供；AI 辅助整理的事实资料稿。编辑可依据来源核实和改写。不是第三方独立评测。

能回答问题，是试用 AI 助手的起点。真正持续使用时，问题会变得更具体：昨天写入的记忆是否准确？这次研究结论来自哪里？代码修改究竟通过了什么测试？这些交接决定了用户能否把下一项任务继续交给助手。

DeepSeekBot 是这一方向上的独立开源社区项目，由 BotHarness 维护，以 `deepseekbot` npm 包安装在 DeepSeek Harness 中。项目提供具有身份和持久记忆的 PersonaBots，支持群组协作、任务委派与 IM 身份。它与 DeepSeek 公司没有官方从属关系，也应与使用 `ds-bot` 包的 DS Bot 分开辨认。

Git-backed memory 是它的一个机制选择。用户可以查看记忆差异和提交历史，判断更新了什么。这个设计提供审阅入口，并不意味着模型写下的内容天然正确。恢复记忆会改变状态，也不能与日常读取混为一谈。

对于知识工作者，一次简报的交接应当包含原始资料和引用，说明哪些是来源事实，哪些是助手推断。对于编码用户，一次修改的交接应当包含 diff、测试命令和实际日志。团队正在围绕这两类小任务准备证据；本稿没有统一任务成功率、耗时或跨产品效果结论。

开源和自托管也带来成本。用户需要维护在线宿主、配置外部应用权限、更新运行环境，并承担模型/API 使用费用。按本稿核查的正式 npm 1.2.0，DeepSeekBot 不包含可选 Computer/Browser Bundles；源码能力和发行包能力应分别说明。

同名项目的出现说明，仅凭“DeepSeek Bot”这个搜索词不够判断工具。更可靠的顺序是先确认维护者和包名，再查看记忆、协作、运行环境与交付方式，最后用一个可验收的小任务决定是否继续使用。

事实来源：[项目 README](https://github.com/BotHarness/DeepSeekBot)、[npm 1.2.0](https://www.npmjs.com/package/deepseekbot/v/1.2.0)、[记忆演化指南](https://deepseekbot.app/docs/channel-sidebar/memory-evolution/)、[同名项目比较](https://deepseekbot.app/blog/deepseekbot-vs-ds-bot/)。

标题：**做了一个持续协作的开源助手 DeepSeekBot，想听听大家怎样审阅 Bot 的记忆和交付**

正文：

> 项目关系说明：这是 BotHarness 的 DeepSeekBot 项目团队自荐，AI 协助整理文案。

我们在做 DeepSeekBot，一个运行在 DeepSeek Harness 中的独立 MIT 开源插件。安装包是 `deepseekbot`，与另一个项目 DS Bot 的 `ds-bot` 分开。

它的主要方向是持续协作：PersonaBot 保留身份和记忆，可以参与群组任务和委派；Git-backed memory 提供差异与历史查看入口，也有 IM 接入。我们比较在意的是交接能不能检查：简报是否带来源，记忆是否能看到变化，代码任务是否交付 diff 与测试日志。

它也需要维护。宿主要在线，模型/API 和应用权限由使用者配置；正式 npm 1.2.0 不含可选 Computer/Browser 组件。这里介绍公开机制，没有统一跑分或替代所有云服务的承诺。

仓库：https://github.com/BotHarness/DeepSeekBot

想请大家讨论一个具体问题：如果把一个长期助手接入你的日常工作，你最先要求它交付哪些证据？是研究引用、记忆差异，还是代码补丁和测试？已有工具在哪个环节让你觉得最难审阅？

答疑备忘：安装细节指向已上线指南；模型/平台支持按当前发行资料回答；不承诺任意微信群聊、迁移兼容、绝对隐私、低成本或比竞品更快。帖子正文已自足，不靠连续贴博客链接引流。
