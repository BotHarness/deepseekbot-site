# 实拍、剪辑与高清视觉交接

本文件是素材请求清单，不是已拍摄的证据。实际执行由 #76/#77 的任务所有者提供；本 slice 不启动其 Profile 或占用其端口。

## 原始素材与公开衍生件

- 录屏尽可能使用原生 1920×1080 或更高可读分辨率；静态图保留原始尺寸。此为本包制作建议，不是声称平台或产品只支持该规格。小尺寸截图不得插值放大后叫高清实拍。
- 先移走私有聊天、工作区、系统通知与凭据；按已授权范围录制。原始记录留在获授权的私有交接位置，未经脱敏不上传 GitHub。
- 对可公开的版本记录语言、主题、实际版本、来源类型（正式 npm／发布标签源码／其他源码）、任务输入与输出位置、审核者和 capture date。内部 Profile ID、账号标识、主机名与私有路径不进公开稿。
- 公开图按审阅用途放 `.github/pr-assets/<实际主题>/`，只有确需页面引用的最终批准图片才按既有内容管线入库。本包不预建空素材或占位“截图”。
- 同一任务的原始稿、人工修改稿与重新运行稿不能互换。修改稿画面标注“人工修正 / human correction”；英文字幕版若复用中文运行，标注其语言来源，不冒充第二次运行。

## 高亮、外框与缩略图

1. 保留一版真实完整界面，让读者识别产品；细节再用特写。屏幕边框只是衍生包装，不画不存在的按钮或对话。
2. 高亮只圈实际来源句、输出句、diff 范围、命令或日志。箭头／字幕避开目标文字，不掩盖失败状态、版本或权限限制。
3. 同屏“原文 → 草稿 → 人工修正”必须来自同一次任务，或明确说明不同 run；不能按好看程度拼成不存在的因果链。
4. 竖版重新取景，不要把整张桌面图等比缩成手机看不清的小块。说明卡可用简洁图形；注明它是示意，不算执行证据。
5. 缩略图采用一处真实焦点画面与一句短文案，团队品牌占次要位置。候选短语见发布备稿；不得加“最佳”“3 分钟完成”“替你省 90% 时间”。

## 导出与字幕

本包建议先剪一个可读的 16:9 主版，再从真实素材单独组织竖版。按实际录制帧率导出，不靠补帧或倒计时包装速度。编码建议和 Shorts 分类规则来自 [平台核验](platform-checks.md)，不是 Bilibili 账号规格已确认。

字幕母表只存 cue 键、语义与结果槽。锁定实际配音／剪辑后再导出 SRT/VTT，逐条核对引用、版本、命令和数字。章节时间由最终文件产生，不把计划镜头顺序直接变成“真实视频时间戳”。

## 发布前人工验收

- [ ] 两种语言完整观看一遍；事实、限定语与失败分支相同，不逐句机械翻译。
- [ ] 手机全屏与桌面各查看来源／diff／日志特写；关键内容无需暂停放大才能识别。
- [ ] 每一条结果句可回指真实证据；结果槽和“待发布”卡没有残留。
- [ ] 原始私有记录未公开；字幕、画面、文件名和通知中没有密钥、路径或账号泄露。
- [ ] 知道哪些等待被剪掉、哪些文字经过人工修正；无法核验的范围仍明确。
- [ ] 第三方来源、fixture、字体、音乐和录音使用权已核对；不用竞品创作者素材冒充本站执行。
- [ ] 实际投稿表单及声明由发布人核对，最终版本／账号／渠道得到具体授权；未授权不上传。
