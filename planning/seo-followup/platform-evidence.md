## 1a. V2EX：可以介绍新作，营销节点和链接搬运边界明确

[官方 FAQ](https://www.v2ex.com/faq)欢迎创业者发布新作品，但反对注册账号后逐个搬运自己网站链接。[链接搬运帮助](https://www.v2ex.com/help/spam)也反对不停粘贴自己站点或受益 aff 链接。它并未禁止一切作者自荐，不能扩大为“V2EX 不允许开源项目发布”。

[节点指南](https://www.v2ex.com/help/node)区分两类：独立开发者新作可以在 [分享创造](https://www.v2ex.com/go/create) 展示；公司的营销内容必须发 [推广](https://www.v2ex.com/go/promotions)。因此这轮若发的是项目团队的品牌推广稿，优先按推广节点准备，不能通过加“开源”二字绕过归类。只选一个合适节点，不跨节点复制同文。

编辑建议：用已核验机制和真实维护取舍介绍作品，正文自足，末尾提出一个具体反馈问题；不贴多篇博客链接、不装第三方用户。不购买 PRO、代发、置顶或广告。FAQ 与节点指南对于发布后编辑/移动时间分别写 5 分钟与 10 分钟，资料存在不一致；发帖前按当日实际界面检查，不在材料中承诺可任意撤回。

## 1b. 技术派：第一方已确认的同名候选是编程社区

[技术派首页](https://paicoding.com/)及[官方上线介绍](https://paicoding.com/article/detail/169)将其定位为 Java 技术社区/开源社区系统；团队署名包括沉默王二、楼仔、一灰。[另一官方上线文](https://paicoding.com/article/detail/155)欢迎写作者入驻，介绍登录和文章编辑模块。[用户协议](https://paicoding.com/article/detail/141)允许按规则发布文章，并要求真实注册资料及尊重他人权利。

目前没有在这些第一方页面找到专门“科技新闻投稿”邮箱、编辑约稿入口或针对 AI/推广的完整发布规则。登录页出现的知识星球绑定审核联系不能当成投稿入口。只能说找到 paicoding.com 这个“技术派”候选，不能说已找到用户所指媒体的编辑邮箱；如果用户指另一个技术派，需要其准确 URL。适配稿应以实际工程信息和知识分享为核心，而不是将其误列为量子位式编辑报道渠道。

## 1c. 微信公众号：本人发布、转载授权、AI 声明、平台原创标识分开

[腾讯官方公众号产品页](https://www.tencent.com/zh-cn/products/official-accounts/)说明个人或组织可以发布内容；自有账号发布与请求别的公众号转载是两项动作，转载授权/署名要另行确定。本次没有账号操作或联系人沟通。

旧规则地址在 Web 文本工具无法打开；直接 HTTP 读取[官方服务协议](https://mp.weixin.qq.com/cgi-bin/announce?action=getannouncement&key=1503979103&version=1&lang=zh_CN&platform=2)返回 200，其正文指向当前[《微信公众平台运营规范》](https://mp.weixin.qq.com/mp/opshowpage?action=newoplaw)。本次直接读取该官方页面内嵌的规则正文返回 200，核验以下条款：

- 3.27 禁止脱离真实创作者表达、由 AI/脚本等替代真人完成创作发布等流程，及批量连续自动发布；3.28 反对高频发布缺乏增量价值的模板内容。不能据此扩写成“禁止任何 AI 辅助”，也不能把人工点一次发布视为自动符合。
- 4.24.2 要求 AI 生成合成内容显著标识，不允许规避平台标识。稿件保留如实声明，发布前核验当前编辑器选项。
- 3.6.1.3 规定主要用于推广、宣传、销售的文章不得声明原创；本人写的品牌稿也不能因此默认勾选平台原创。整合引用、非独家授权等内容另有边界。

[原创声明功能官方条款](https://mp.weixin.qq.com/cgi-bin/announce?action=getannouncement&key=1463730026&version=1&lang=zh_CN&platform=2)直接读取为 200，要求作者拥有发表权或合法有效完整授权。平台原创标识和著作权归属不是同一个判断，也不能承诺媒体/其他公众号能替我们声明原创。最终标题、正文、真人作者贡献和发布表单由账号持有人审核，当前只交付待审稿。

## 2. 知乎：自发布问答与专栏，不是媒体投稿

- [官方创作者手册](https://www.zhihu.com/knowledge-plan/manual)说明问答、文章/专栏等创作形态，并介绍寻找合适问题的方式。本次 Web 文本抓取超时，直接 HTTP 读取同一官方页面返回 200，标题为“创作者手册 - 知乎”。建议依据实际用户问题改写，不能编造现有热门问题或声称已有搜索量。
- [知乎协议](https://www.zhihu.com/plainterms)要求发布者拥有著作权或合法授权。作者可以使用自己的稿件；引用其他项目 README、截图和视频仍需核实权利与适当引用范围。
- [机构号使用规范（试行）](https://www.zhihu.com/org_use_norm)明确反对诱导点赞、私信恶意营销、重复低质导流和同文多问重复回答。该规范对机构号有额外约束，不能冒充其适用于所有个人账号的完整政策。真实开发者身份也不应被包装成第三方独立用户。
- [关于应用 AIGC 能力进行辅助创作的社区公告](https://zhuanlan.zhihu.com/p/624717941)本次返回 403，不能把其他网站转载当作已核验全文。[官方创作模版活动规则](https://www.zhihu.com/parker/campaign/1678437528674504704)可读，明确说明包含 AIGC 内容应主动使用“包含 AI 辅助创作”标签；这是活动证据，不应扩写成已读完当前全部普通社区 AI 规则。备稿保留 AI 辅助说明，发布前核验编辑器实际声明项。
- [普通社区管理规定](https://www.zhihu.com/term/community)本次直接和 Web 读取均为 403。普通账号的具体外链限制、编辑器是否支持指向外站的 canonical、当前 AI 标记流程都记为未知。

稿件做法：正文自足，开头说明与项目关系；按读者选择任务解答，给出 owner/repo/package 查验方法与来源；不要只留一个“完整内容请去官网”的广告摘要。是否可放官网原文链接以发布页现行规范为准，不保证被搜索引擎收录。

## 4. Hashnode：英文备稿适合，但不以 SEO abuse 为目的

[Hashnode Code of Conduct](https://hashnode.com/code-of-conduct)页面标记最后更新 2026-06-04，要求作者负责原创性和准确性；允许 AI 生成内容，但必须审核并承担责任；禁止 spam、批量自动内容、SEO abuse 和主要用于自我推广而不贡献社区价值的行为。技术文章及相关文档/仓库引用被允许。故工程解释可以作为候选，纯广告、标题党、批量搬运不适合。

[Hashnode 官方源码发布模板](https://github.com/Hashnode/Hashnode-source-from-github-template)的 `canonical`/`canonicalUrl` 支持原文地址；[官方 GraphQL schema](https://github.com/Hashnode/gql-skill/blob/main/skills/gql-api/references/schema.graphql)的 `PublishPostInput.originalArticleURL` 明确是转载文章 canonical。这里只核验功能定义，没有调用发布 API 或配置自动同步。

旧[编辑器文档](https://docs.hashnode.com/blogs/editor/writing-a-blog-post)的第一方搜索缓存说明 `Add Original URL`，但本次该链接及 docs 根域直接 HTTP 都返回 404。不能把旧按钮说明写成已核验当前 UI。发布前在真实编辑器检查原文字段，再检查已发布 HTML。

如果英文外部版本与官网英文文章重复/高度相似，指向相应英文原文；不要用中文原文或主页代替。若独立改写成另一个任务/意图，不能为了回传权重硬设一个不等价 canonical。Google 将 canonical 视为规范化信号，搜索引擎最终仍会选择 canonical，不能承诺原站排名优先或流量增加。[Google canonical 官方说明](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)

## 5. DEV：专门 AI 规则的精确适用边界

两组规则同时适用，不能只读 canonical 帮助页：

1. [DEV Terms，Content Policy](https://dev.to/terms)：内容应相关、有质量，主要目的不能是推广或创建反向链接；文章要有实质内容，不能仅跳转外站全文。用户要拥有发布内容权利，不能复制他人作品。
2. [DEV 官方 AI-assisted Articles 指南](https://dev.to/guidelines-for-ai-assisted-articles-on-dev/)（页面标记更新 2024-04-08）：AI 辅助/生成文章要求披露、事实核查，并规定：

   > Promote any business, program, or course (including your own).

   这句话位于“AI-assisted and -generated articles should not”之下。它约束 AI 辅助/生成稿件，并非宣布所有作者、所有开源项目文章都禁止分享。对我们当前由 AI 协助准备且以品牌推广为目标的稿件，不能预先判定可发。另有主要目的为 SEO backlinks 的限制及个人博客/组织博客例外，但例外不消除前面的 AI 推广限制或通用内容政策。

3. [DEV 组织内容导入帮助](https://dev.to/help/organizations/importing-your-organizations-content)：反对纯推广稿，支持 RSS 原文 canonical、编辑器字段或 `canonical_url` frontmatter。**有组织账号和 canonical 只说明归属与转载功能，不代表稿件获得合规豁免。**

因此本轮不做“可直接发 DEV 的 AI 品牌稿”。未来如果由真人作者基于自己理解的工程实践写知识分享，可重新评估上述规则；如仍使用 AI 辅助必须如实披露，不能通过删声明或假装人工写作规避。需要平台澄清的地方留作待核验；本轮没有发邮件。
