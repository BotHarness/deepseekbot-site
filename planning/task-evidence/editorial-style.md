# 实测博客的读者文风

本次用户反馈：文章要介绍一个想法、一件事和从中得到的经验，不能把内部核验文档搬进正文。此规则适用于这两篇双语任务博客和后续文案交接。

先写为什么尝试、怎么做、发生了什么、下次会怎样做。用具体动作代替“资格验证、路由核验、交付范围”等内部流程措辞。技术词只在读者需要操作或理解结果时出现，优先用日常说法；代码、错误名和界面里的实际入口可以保留。

图题说明观察点，图注通常只需一句。示例对话写“示例对话”，原始中文回复写“中文原文”，即可避免误导。图片版本、像素、来源哈希、重拍过程、组件资格和编辑检查记录保留在证据文件中，不逐图重复。

失败和人工介入属于故事，放在发生的位置说清楚。正文保留会改变读者判断的事实：材料由我们预选，输出超长，Bot 执行失败而手动运行通过，额外文件及环境清理问题。可展开的文末记录供复现者查模型、版本、费用与原始文件，不能用它隐藏失败或包装成功。

中文和英文分别写得自然，事实和结论一致。不补造体验、对话、速度、成功率或竞争结论。原始输出、生成代码、日志和截图保持不变。
